## 0.1 PocketTerm35 套件硬件事实（后续核实）

这台设备不是“树莓派 + 外接充电宝”，而是**微雪 PocketTerm35 手持终端套件**：

- 官方支持 Raspberry Pi 4B / 5；屏幕为 3.5 英寸 640×480 HDMI 触摸屏
- **套件自带 UPS 电源管理系统，支持边充边放**
- 内置电池：3.7 V、5000 mAh 聚合物锂电，PH2.0 两针接口；官方建议约 `67 × 55 × 12 mm`，最大放电电流不低于 3 A，保护板过流阈值不低于 5 A
- Pi 与套件的连接：mini-HDMI（视频）、USB Type-C（键盘 Pico）、顶针接触 40 针排针（供电/触摸相关），电池接 PH2.0，另有扬声器接口
- 键盘控制器实测为 `1209:0001 My Custom Pico`，同时枚举 CDC-ACM、HID 键盘/鼠标及 USB Audio 接口

官方资料：[`PocketTerm35 产品说明`](https://docs.waveshare.net/PocketTerm35/)、
[`组装说明`](https://docs.waveshare.net/PocketTerm35/Assembly-Guide/)、
[`软件配置`](https://docs.waveshare.net/PocketTerm35/Software-Guide/)、
[`FAQ`](https://docs.waveshare.net/PocketTerm35/FAQ/)。

### 电源键的正确用法（Pi 4 版本）

| 操作 | 作用 | 注意 |
|---|---|---|
| **单击顶部电源键** | 开机 | 官方组装说明的操作 |
| **系统内关机** | 安全关闭 Raspberry Pi | Pi 4 没有 Pi 5 那个侧面软件电源键；可用桌面菜单或 `systemctl poweroff` |
| **系统完全关机后双击顶部电源键** | 切断套件电源/电池输出 | 必须先等系统关机完成；不要在系统运行时双击，避免文件系统损坏 |

官方 FAQ 的流程是：**先系统关机，等待设备完全关机；如有需要，再双击顶部电源键断开电源**。
FAQ 中提到的“短按 Pi 5 侧面硅胶按键关机”只适用于 Pi 5，不适用于本机 Pi 4B。

### 四颗红色电量 LED 的结论

四颗电量指示灯属于 PocketTerm35 的**电源 PCBA 自己驱动的硬件指示**，不是 Pi 的软件 LED：

- `/proc/device-tree/hat/` 无 HAT EEPROM
- I2C-1 只有 `0x51`（PMIC）和 `0x5d`（触摸屏），没有电源板 MCU/电量计
- `leds-gpio` 驱动未绑定，GPIO pinmux 没有电量 LED 输出脚
- 官方 `3.5HDMI_E_DTBO.zip` 只含 `waveshare-35dpi-3b/4b/5b` 三个触摸屏 overlay；与本机文件逐个 MD5 核对完全相同，没有电源控制定义

因此 **Pi 无法通过脚本或 GPIO 让这四颗灯“按键亮 5 秒后灭”**。不拆机的可行方案只有光学处理：

1. 首选：在 LED 窗口贴深色半透明柔光片/磨砂胶带，保留电量可见性但降低刺眼程度
2. 黑色电工胶带或黑色亚克力片：完全遮光
3. 黑色油性笔/指甲油：降低亮度，但不可逆

如果以后愿意打开后壳，才可以测量 LED 驱动方式后加实体开关或“按钮 + 555/RC+MOSFET 五秒单稳态”。

### 屏幕亮度

微雪 FAQ 与 PocketTerm35 键盘资料确认，背光由 Pico RP2040 的 **GP20 PWM** 控制；标准固件的 `Fn + -` / `Fn + =` 直接调亮度，所以**不需要 `/sys/class/backlight`，Linux 找不到该目录是正常的**。

本机没有安装主机侧 `pt35d` / `pt35ctl` / `pocketterm-brightness`，Pico 的 `ttyACM0` 目前是 CDC-ACM。工作区 ``PocketTerm35-OS 硬件说明``（第三方项目，见其自身仓库）记录的脚本化控制需要**支持 `B<0-100>` 串口命令的定制 Pico 固件 + `pt35d`**；当前并未部署。不要把这条“屏幕背光可由 Pico 调节”的路径与四颗电量 LED 混为一谈，后者仍由套件电源板硬件驱动。

> 如需快捷键调节，直接试实体键盘 `Fn + -` / `Fn + =`。如需 Linux 脚本/滑块调节，应先评估并备份键盘固件，再单独部署 `PocketTerm35-OS` 的 Pico 固件和 `pt35d`，不要直接刷写。

## 1. WiFi 无法连接

### 1.1 症状

GUI 里点击连接 `MyWiFi` 一直失败；换连 `MyWiFi` 也失败。

### 1.2 根因（两个独立问题叠加）

**问题 A — 保存的配置文件指向不存在的 SSID**

| 项 | 值 |
|---|---|
| 保存的 Profile | `MyWiFi`，`hidden=yes` |
| 实际扫描结果 | **全网络不存在该 SSID** |
| 结果 | NetworkManager 报 `reason 'ssid-not-found'`，必然失败 |

`hidden=yes` 也属误配：该网络并不隐藏，会让 NM 反复做定向探测（NM 自己都会警告
`active scanning ... makes you trackable`）。

**问题 B — 目标 AP 在 2.4G 广播 802.11ax，把树莓派的 brcmfmac 固件拖入坏状态**

目标 AP 是 `MyWiFi`（BSSID `aa:bb:cc:dd:ee:ff`），后确认为
**Generic AP**（运营商定制路由器，LAN `192.168.1.1`，LAN MAC `aa:bb:cc:dd:ee:ff`）。

关键证据链：

| 检查 | 结果 |
|---|---|
| Pi 无线硬件/驱动/固件 | 正常（BCM4345/6，固件 `7.45.265` 已加载，rfkill 无阻挡）|
| **关联能力对照**（开放 AP `Tineco_8541`，**-74 dBm**）| ✅ 一次成功 → Pi 侧无问题 |
| 目标 AP（**-25 dBm**，信号极强）| ❌ **6 成功 / 162 次 ≈ 3.7%**，成功成簇出现在约 20 秒的窗口内 |
| 失败位置 | **认证阶段**，四次握手从未开始 → 与密码无关 |
| 内核报错 | `status 16: Authentication rejected due to timeout waiting for next frame in sequence`（brcmfmac 自己的占位码，非 AP 回包）|
| 客户端变量穷举 | 省电、锁 BSSID、真实/随机 MAC、监管域对齐 CN、关 WPS、限发射功率 → **全部无效（0/44）** |
| **重载 `brcmfmac` 模块** | **8/8、6/6、6/6 = 100%** |
| A/B/A 换固件版本 | 三阶段全 6/6 → **与固件版本无关，是运行时状态卡死** |

**结论**：AP 在 2.4G 上广播 **HE(11ax) + VHT**（含 `HE40/2.4GHz`，非标准组合），
导致 Pi 的 brcmfmac 固件进入"能收信标但无法完成认证"的坏状态。重载模块可临时恢复，
但会再次卡死。

### 1.3 修复

**AP 侧（根因修复）**：在 GenericAP 管理页把 **2.4G 无线模式从 11ax 改为 802.11 b/g/n 混合**。

验证改动生效（信标对比）：

```
改动前：HT + VHT capabilities + HE capabilities + "HE40/2.4GHz"
改动后：HT + VHT 保留，HE capabilities / HE PHY Capabilities 消失 ✅
```

修复后：**7 次关联成功、0 次被拒**，重启后依然稳定。

**Pi 侧（配合）**：

```
# 删除失效 profile（已备份到 /root/nm-backup-MyWiFi.nmconnection）
nmcli con delete "MyWiFi"

# 新建正确 profile
# /etc/NetworkManager/system-connections/MyWiFi.nmconnection
[connection]  id=MyWiFi / autoconnect=true
[wifi]        ssid=MyWiFi / mode=infrastructure / powersave=2
[wifi-security] key-mgmt=wpa-psk / psk=<见 .secrets> / wps-method=1
```

### 1.4 若以后再卡死（应急恢复）

```bash
nmcli device set wlan0 managed no
nmcli device disconnect wlan0
ip link set wlan0 down
modprobe -r brcmfmac_cyw; modprobe -r brcmfmac
modprobe brcmfmac_cyw; modprobe brcmfmac
sleep 12
nmcli device set wlan0 managed yes
```

> 模块可热重载，**不需要重启**。

## 2. 双网卡同网段 → ARP flux

### 2.1 症状

WiFi 修好后，eth0 与 wlan0 交替丢包；SSH 会话偶发中断（`No route to host`）。

### 2.2 根因

GenericAP 是**桥接 AP**（客户端拿到的也是 `192.168.1.x`），因此
**Pi 的 eth0 和 wlan0 处在同一二层网络、同一网段**。

默认 `arp_ignore=0` 时，**两个接口都会用自己的 MAC 应答对方 IP 的 ARP 请求**，
导致对端 ARP 缓存指向错误 MAC：

```
修复前（本机 ARP 缓存）:
  192.168.1.102 -> aa:bb:cc:dd:ee:ff   (eth0 真实 MAC)
  192.168.1.102 -> aa:bb:cc:dd:ee:ff   (wlan0 MAC)  ← 错误条目
```

### 2.3 修复

`/etc/sysctl.d/90-arp-multihomed.conf`：

```
net.ipv4.conf.all.arp_ignore = 1
net.ipv4.conf.default.arp_ignore = 1
net.ipv4.conf.eth0.arp_ignore = 1
net.ipv4.conf.wlan0.arp_ignore = 1

net.ipv4.conf.all.arp_announce = 2
net.ipv4.conf.default.arp_announce = 2
net.ipv4.conf.eth0.arp_announce = 2
net.ipv4.conf.wlan0.arp_announce = 2
```

生效后 ARP 缓存每个 IP 只对应一个正确 MAC，两接口 0% 丢包。

**回滚**：删除该文件后 `sysctl --system`。

## 3. 屏幕永不熄灭

### 3.1 症状

桌面空闲后屏幕一直亮着，从不熄屏。

### 3.2 根因（发行版配置缺口）

```
会话类型: Wayland / labwc（不是 Xorg）

xset q  → "Server does not have the DPMS Extension"
          Screen Saver timeout: 0
```
`xset` 打到的是 **XWayland 兼容层**，它不实现 DPMS（不拥有显示输出），所以 X 侧怎么设都无效。

**真正的问题**：

```
swayidle = /usr/bin/swayidle   ← 已安装
wlopm    = /usr/bin/wlopm      ← 已安装

/etc/xdg/labwc/autostart 只有 4 行:
  lwrespawn pcmanfm-pi &
  lwrespawn wf-panel-pi &
  kanshi &
  lxsession-xdg-autostart
  ↑ 没有启动 swayidle

在 labwc 配置里搜 idle/blank/dpms/wlopm/swayidle → 零命中
```

**Raspberry Pi OS 装了熄屏工具却从未在 labwc 中启动它们。**

> 排查陷阱：`/sys/class/graphics/fb0/blank` 读数为 `4`（POWERDOWN）会让人误以为已熄屏。
> 这是**遗留 fbdev 兼容层的假状态**，以 KMS 为准：`/sys/class/drm/card1-HDMI-A-1/dpms`。

### 3.3 修复

新建 `/home/user/.config/labwc/autostart`，**完整保留原 4 行**并追加：

```
/usr/bin/swayidle -w timeout 180 '/usr/bin/wlopm --off "*"' resume '/usr/bin/wlopm --on "*"' &
```

- 空闲 **180 秒** → 关 HDMI 输出；任意键鼠/触摸输入 → 立即恢复
- 注意：用户级 autostart **会覆盖**系统级，所以必须包含原有全部行
- 已验证：60 秒测试版在 70 秒后 `dpms: Off`

### 3.4 实测结论：这是**真省电**

熄屏后屏幕是**全黑（背光也灭）**，不是发灰的亮屏。
因为该屏是 **HDMI 屏**（自带控制器板、有 EDID），信号断开时会自行关闭背光——
这与背光硬接 5V 的 DPI 裸屏完全不同。**预计省 0.3–0.5 W。**

### 3.5 手动控制

```bash
export XDG_RUNTIME_DIR=/run/user/1000 WAYLAND_DISPLAY=wayland-0
wlopm                      # 查看状态
wlopm --off '*'            # 立即熄屏
wlopm --on  '*'            # 立即点亮
```

## 4. VL805 USB 控制器发热处理

### 4.1 背景

用户反馈 **USB-A 口 + 网口那一侧发热**。定位到两个嫌疑：

| 芯片 | 位置 | 空闲功耗 | 说明 |
|---|---|---|---|
| **VL805/806 xHCI** (`1106:3483`) | USB-A 口旁 | 0.3–0.6 W | PCIe Gen2×1 端点，D0 全功率，无散热片 |
| **BCM54213PE 千兆 PHY** (`phy_id=0x600d84a2`) | RJ45 与 USB-A 之间 | 0.5–0.7 W @1Gbps | 满速千兆时显著发热 |

### 4.2 处理：禁用 PCIe（官方支持）

`/boot/firmware/overlays/README` 中（**2711 即 Pi 4 专用**）：

```
pcie    Set to "off" to disable the PCIe interface (default "on")
        (2711 only, but not applicable on CM4S)
        N.B. USB-A ports on 4B are subsequently disabled
```

在 `/boot/firmware/config.txt` 末尾（属于 `[all]` 段）追加：

```
dtparam=pcie=off
```

> 另：`dtparam=pciex1_gen`（PCIe 降速）是 **2712/Pi 5 专用，Pi 4 不支持**，此路不通。

**运行时等效手段**（立即生效，无需重启）：

```bash
# /etc/systemd/system/vl805-unbind.service（已安装并 enable）
echo 0000:01:00.0 > /sys/bus/pci/drivers/xhci_hcd/unbind    # 停用
echo 0000:01:00.0 > /sys/bus/pci/drivers/xhci_hcd/bind      # 恢复
```

**安全性验证**：

```
解绑后：Bus 1/2（VL805）消失，只剩 usb3（DWC OTG）
        Pico 键鼠 / hidraw0 / ttyACM0 全部完好 ✅
        触摸屏（I2C 0x5d）完好 ✅
```

> 键盘鼠标走 **DWC 控制器（Bus 3）**，不经 VL805，所以禁用 USB-A 不影响输入设备。

> ### ⚠️ 重要更正：`unbind` 只解除驱动绑定，**不等于断电**
>
> 事后核对发现芯片仍在通电、PCIe 链路仍在训练：
>
> ```
> 0000:01:00.0 (VL805): driver=无   enable=0   但 link_speed=5.0 GT/s   ← 链路仍训练
> 0000:00:00.0 (桥):    driver=pcieport  power_state=D0  link 5.0 GT/s
> ```
>
> xHCI **功能**停了（Bus1/Bus2 消失），但 **PCIe PHY 与 PLL 仍在运行**。
> **实际省电远小于最初估计的 0.3–0.6 W，大约只有 0.05–0.15 W。**
>
> **真正的断电必须靠 `dtparam=pcie=off` + 重启**（开机即不训练链路）。
> 这也进一步解释了为何禁用它之后"手感温度"没有变化。
>
> **教训：`unbind` ≠ 断电。要真正断电必须让固件在启动阶段就不初始化该设备。**

**回滚**：

```bash
systemctl stop vl805-unbind        # 临时
systemctl disable --now vl805-unbind   # 永久（并删除 config.txt 中的 dtparam=pcie=off）
```

### 4.3 实测结论：**没有解决手感发热**

禁用 VL805 后用户反馈"**还热**"，拔掉网线后仍然热。原因是这两个加起来才省 0.5–1 W，
而 **SoC 单独就占整块板 2.5 W 中的约 2 W**，主导了板级温度。详见 §6。

**保留价值修正**：由于运行时 `unbind` 并未真正断电（见上），其省电约 **0.05–0.15 W**，
对续航与温度都影响甚微。**要拿到完整的 0.3–0.6 W，必须重启让 `dtparam=pcie=off` 生效**
（重启后 PCIe 设备应完全消失，可用 `lspci` 验证为空）。

## 5. 配置冗余：两个触摸屏 overlay

`config.txt` 同时加载了两个 overlay，二者内容已解编译确认：

| overlay | 大小 | `compatible` | 声明内容 |
|---|---|---|---|
| `waveshare-35dpi-4b` | 635 B | `brcm,bcm2708` | **仅** Goodix GT911 @ I2C `0x14` |
| `waveshare-35dpi-5b` | 1001 B | `brcm,bcm2835` | GT911 @ `0x14` **和** `0x5d` |

实际硬件与驱动绑定：

```
1-005d : name=gt911  → Goodix-TS  → 生成 input6（真实可用触摸屏）✅
1-0014 : name=gt911  → 无驱动绑定（i2cdetect 扫不到 0x14）= 幽灵设备
```

**结论**：`waveshare-35dpi-4b` 是多余的（只造了个幽灵 I2C 节点），真正干活的是
`-5b` 里的 `0x5d`。

> 重要更正：`-4b`/`-5b` **不是 DPI 显示 overlay**，名字有误导性。
> 它们只定义触摸屏，**不占用 GPIO 0–27**，对功耗和温度**零影响**。
> 清理此项属配置卫生，无实际收益，且判断失误会导致触摸失效，故**暂未改动**。

## 6. 热与功耗实测分析

### 6.1 负载测试：**满载严重降频**

| 阶段 | 温度 | ARM 频率 | throttled | 状态 |
|---|---|---|---|---|
| 待机 | 65.7–66.2 °C | 600–800 MHz | `0x0` | 正常 |
| 满载 20 s | 80.3 °C | **1500 MHz** | `0x0` | 正常 |
| 满载 40 s | 81.8 °C | 1475 MHz | `0x80008` | 触及 85 °C 软温度墙 |
| 满载 60 s | 83.7 °C | 1280 MHz | `0xe0008` | 开始降频 |
| 满载 120 s | 84.7 °C | 1231 MHz | `0xe0008` | 持续降频 |
| 满载 160 s | **85.2 °C** | **600 MHz** | `0xe0006` | **正在降频，损失 60% 性能** |
| 卸载后 60 s | 72.0 °C | 600 MHz | `0xe0000` | 恢复（标志位仅历史）|

**throttle 位解读**：

```
0x80008 = bit3  + bit19              → 已触及 85°C 软温度墙
0xe0008 = + bit17 + bit18            → 已发生 ARM 频率封顶 + 降频
0xe0006 = + bit1 + bit2              → 【当前正在】频率封顶 + 降频
```

**判断：散热不足。** 加散热器**不省电**（只省漏电流约 0.05 W），但能**救回那 60% 性能**
并让整板降温。

### 6.2 为什么"两侧都热"

SoC（BCM2711）在板子正中央，是 ~2.5 W 里约 2 W 的来源，通过 PCB 铜层向两边扩散。
所以左（PMIC/USB-C 侧）右（网口/USB-A 侧）都热。

**待机 66 °C 偏高**（裸 Pi 4B 在 25 °C 室温通常 50–60 °C），可能主因：
**屏板以顶针架在排针上，覆盖 SoC 上方，形成隔热空腔、切断对流。**

### 6.3 整机功耗构成

| 单元 | 功耗 | 占比 | 能否软件处理 |
|---|---|---|---|
| **Pi 4B 主板**（SoC+RAM+PMIC 损耗）| ~2.5 W | **56 %** | 只能 halt |
| **PocketTerm35 UPS DC/DC 损耗** | ~0.5–0.7 W（估算） | 13 % | 换高效率电源路径 |
| 千兆以太网 PHY | ~0.3–0.5 W | 9 % | ✅ 降 100M 或拔线 |
| 屏幕（背光 + 面板/管线）| ~0.3–0.45 W | 8 % | ✅ 已用 swayidle 熄屏 |
| WiFi + 蓝牙 | ~0.2–0.4 W | 7 % | ✅ 关射频 |
| USB Hub + Pico | ~0.15–0.3 W | 5 % | 拔掉 |
| **合计** | **~4–5 W** | 100 % | |

**实测反推**（PocketTerm35 内置 5000 mAh 电池，用户报告续航约 3–4 小时；以 DC/DC 效率 85% 粗估）：

```
5000mAh @3.7V = 18.5 Wh，按 85 % 转换效率 → 可用约 15.7 Wh
  3.0 小时 → 整机约 5.2 W      3.5 小时 → 整机约 4.5 W      4.0 小时 → 整机约 3.9 W
```

> 这是根据额定电量与用户报告的运行时间反推，并非输入端功率表实测；电芯可用容量、截止电压和转换效率都会影响结果。

> Pi 4B **没有输入电流传感器**（`pmic_read_adc` 未注册、`hwmon` 只有 `cpu_thermal` 与
> `rpi_voltage`），软件读不到含 USB 外设的总功耗。**精确值需 USB 电流表。**

### 6.5 待机能力：**Pi 4 不支持休眠**

内核编译时就没编进去：

```
# CONFIG_SUSPEND is not set        ← 没有 S3（挂起到内存）
# CONFIG_HIBERNATION is not set    ← 没有 S4（挂起到磁盘）
CONFIG_ARCH_SUSPEND_POSSIBLE=y     ← 架构"可以"，但固件没接口
/sys/power/state = 空
cpuidle driver: none
/proc/device-tree/cpus/cpu@0/enable-method = spin-table   ← 不是 PSCI
/proc/device-tree/psci/ = 不存在
```

ARM64 实现挂起需要 **PSCI** 固件接口，**Pi 4 用老式 spin-table，没有 PSCI**。
官方定论见 [raspberrypi/firmware#1635](https://github.com/raspberrypi/firmware/issues/1635)：
*"Hibernation (suspension to disk), sleep (suspension to memory, low-power mode) remain unsupported."*

**换发行版会更糟**：启用 `CONFIG_SUSPEND` 的发行版（如 Fedora）会让 Pi 进入 s2idle 后
**醒不过来**——见 [Red Hat #2283978](https://bugzilla.redhat.com/show_bug.cgi?id=2283978)、
[openSUSE #1234355](https://bugzilla.opensuse.org/show_bug.cgi?id=1234355)、
[raspberrypi/firmware#1931](https://github.com/raspberrypi/firmware/issues/1931)。

### 6.6 唯一已验证的低功耗路径：halt

| 配置 | halt 后功耗 | 唤醒方式 | 说明 |
|---|---|---|---|
| 运行中 | 4.5 W | — | 当前整机估算 |
| `WAKE_ON_GPIO=1`（**当前默认**）| **约 1.85 W** | **GPIO3 或 GLOBAL_EN 短接到地** | 本机已知可用的 halt 路径 |
| `POWER_OFF_ON_HALT=1` | — | — | **不要用于本机 Pi 4：该 EEPROM 选项属于 Pi 5，当前 Pi 4 配置未提供** |

> **重要更正**：此前把 `WAKE_ON_GPIO=0 + POWER_OFF_ON_HALT=1` 和 0.20 W/78.5 小时续航写进了 Pi 4 方案；该设置不是本机 Pi 4 的可用选项，相关数字应视为撤回，不再作为 Frank-Pi 设计依据。

**PocketTerm35 的正确低功耗流程**：先在系统内 `systemctl poweroff`，确认 Pi 完全关机；如需彻底断开套件电源，再双击顶部电源键。它是“安全关机 + 硬件断电”，不是休眠恢复。

**核心限制：Pi 4 没有可用的内存休眠/挂起；低功耗只能走 halt 或 PocketTerm35 的硬件断电。**

> 发行说明中关于 `POWER_OFF_ON_HALT` 的描述不能直接套用于本机；Pi 4 当前只确认 `WAKE_ON_GPIO`。

> ⚠️ **低功耗供电注意**：通用充电宝可能因低电流保护而自动断电。Frank-Pi 使用 PocketTerm35 内置 UPS，
> 其在 `halt` 状态下是否保持输出、静置多久是否自动关断，尚未实测；不要直接套用通用充电宝结论，需在现场验证。

### 6.7 背光不可软件控制？—— **已推翻**

该屏是 **HDMI 屏**（`YDK WS-35-640`，有 EDID，自带控制器板），
熄屏时**背光会自行关闭**（用户确认全黑）。因此 §3 的熄屏方案是**真实有效的省电措施**。

## 10. 方法论备注（本次踩过的坑）

1. **`/sys/class/graphics/fb0/blank` 会骗人** —— vc4-kms-v3d 下必须看
   `/sys/class/drm/*/dpms`。
2. **`xset` 在 Wayland 会打到 XWayland** —— 报 "no DPMS Extension" 不代表系统有问题，
   要查合成器侧（labwc → swayidle/wlopm）。
3. **`vcgencmd display_power` 在 KMS 下是空操作** —— 实测执行后返回值不变。
4. **板级发热不能只看 SoC 温度** —— Pi 4 只有 `cpu_thermal` 一个温度传感器，
   无法软件定位 VL805 / PHY 温度；必须靠"拔掉/禁用某个部件后用手感受"来二分定位。
5. **AP 的 2.4G 广播 11ax 会让 Broadcom fullmac 客户端卡死** —— 表现为
   "能扫到、能收信标、认证无响应"，成功率极低且成簇出现，极易被误判为硬件故障。
6. **不要被单次成功误导** —— 需要 A/B/A 交叉对照才能确认因果（本次 T2 组的 3/6
   一度被误认为配置生效，交叉对照后证明是时间窗口）。
