## 三、★ 第二个教训：**每帧调 `systemctl` 会毁掉帧率**

```python
# ❌ 初版：每帧查询服务状态
for frame in ...:
    if active('NetworkManager.service'):   # subprocess.run ≈ 15-20ms
        ...

# 实测：18fps 目标（55ms/帧），其中 20ms 被 subprocess 吃掉
# → 实际掉到 ~8fps，18 秒才走到 27%（预期 55%）
```

```python
# ✅ 修正：加 TTL 缓存 + 降低查询频率
_active_cache = {}
def active(unit, ttl=0.6):
    now = time.time()
    hit = _active_cache.get(unit)
    if hit and (now - hit[1]) < ttl:
        return hit[0]
    ...
# 并且阶段判定改为每 12 帧才查一次
```

**修正后**：20 秒 → 85%（与设计曲线吻合）

## 四、★ 第三个教训：**`ExecStopPost` 同步重试会超时**

```ini
# ❌ 错误：同步重试启动 kmscon
ExecStopPost=-/bin/sh -c 'for i in 1..5; do systemctl start kmsconvt@tty1 && break; sleep 2; done'
# 问题：此刻 sway 还占着 DRM master，kmscon 必然失败
#       → 阻塞 10 秒 → State 'stop-post' timed out → 服务 failed
```

```ini
# ✅ 正确：异步 + 等桌面就绪
ExecStopPost=-systemd-run --collect --quiet --unit=pt35-boot-rescue \
    /bin/sh -c 'for i in $(seq 1 20); do systemctl is-active --quiet pt35-desktop.service && break; sleep 1; done; ...'
```

**结果**：`Result=success`、退出码 0、无超时

> 这和 `zhdesk` 的问题是同一类：
> **systemd 停止服务时会向整个 cgroup 发 SIGTERM**，
> 里面的 `systemctl` 子进程会被杀掉 → 恢复动作必须**脱离 cgroup**。

## 五、部署结构

```
/usr/local/bin/pt35-bootsplash                    # 渲染脚本（纯 Python 标准库）
/etc/systemd/system/pt35-bootsplash.service       # 开机动画服务
/etc/systemd/system.conf.d/10-quiet-console.conf  # ShowStatus=no（避免抢屏）
/etc/systemd/system/pt35-desktop.service          # 桌面自启（之前已建）
```

**时序**：
```
0s    内核启动
~2s   pt35-bootsplash 开始（DefaultDependencies=no，尽早）
~27s  动画跑完 100%，脚本自行退出
~29s  ExecStopPost 异步恢复 kmscon
~30s  pt35-desktop 启动 sway + foot + fcitx5
```

**为什么 25 秒**：kmscon/pt35-desktop 约 30 秒接管屏幕，动画必须在之前跑完。

## 八、如果要做其它风格

这次踩的坑对**任何**终端 UI 设计都适用：

1. **先用真机截图验证字符集**，再开始设计
2. **低分辨率（80×30）下优先用数学生成的图案**
   - 共振/克拉德尼图形（`sin(mπx)·sin(nπy)`）→ 振幅映射字符密度，天然抗锯齿
   - 曲面 3D 网格在 2400 格下必然有锯齿（信息量限制，不是算法问题）
3. **每帧只做必要的计算**，I/O 和外部命令要缓存
4. **恢复/清理动作必须异步且脱离 cgroup**

# 补充：老电视故障效果（雪花 / 串扰 / 撕裂）

**需求**：在原有"稳定"的画面上加入**干扰、串扰、老电视雪花**。

## 一、★ 核心设计矛盾：故障 vs 可读性

开机画面必须让人**看清启动进度**，但满屏雪花会糊掉文字。
实测第一版把 `P O C K E T T E R M` 打成了 `P O C K E T T:E R M` → 不可接受。

**解决方案：分层干扰 + 关键行保护**

| 层 | 效果 | 是否影响文字 |
|---|---|---|
| 雪花底噪 | 随机 `░▒▓█·.:+*#\|/` 散点 | ❌ **只填原本是空白的格子** |
| 信号丢失 | 块字符 `█` → `▒` | ⚠️ 保护行跳过 |
| 横向撕裂 | 整行左右偏移 1-2 字符 | ⚠️ 保护行跳过 |
| 场同步失败 | 整屏上移一行 | ⚠️ 短暂，立即恢复 |
| 滚动条带 | 一条亮带持续缓慢上滚 | ❌ 背景层 |

**保护行白名单**（这些行的内容禁止被破坏）：
```python
PROTECTED_KEYS = (
    'P O C K E T T E R M',    # 设备名
    'RESONANCE FIELD',        # 共振进度条
    'starting',               # 阶段文字
    '+ ',                     # 百分比
)
```

> **实测效果**：严重故障时背景满屏雪花、屏幕抖动、出现 `SIGNAL LOST /
> CROSSTALK DETECTED`，但设备名、进度百分比、阶段文字**完全可读**。

## 二、★ 关键：故障要"周期性"，不能持续

持续噪声很吵，而且不像真实老电视。用**状态机**做"稳定 → 抖动 → 恢复"：

```python
class GlitchCycle:
    def step(self):
        if self.burst > 0:
            self.burst -= 1
            return 0.15 + self.rng.random() * 0.85    # 爆发中
        self.cooldown -= 1
        if self.cooldown <= 0:
            if self.rng.random() < 0.30:               # 30% 概率爆发
                self.burst = self.rng.randint(3, 8)    # 持续 3-8 帧
                self.cooldown = self.rng.randint(14, 30)
                return 0.15 + self.rng.random() * 0.85
            self.cooldown = self.rng.randint(5, 12)
        return 0.0                                     # 稳定
```

**观感**：大部分时间干净稳定，偶尔"现实破裂"几帧 —— 这正好呼应
《控制》里 **Hiss 侵蚀现实**的设定。

## 三、性能：噪声场要缓存

```python
# ❌ 每帧生成整屏 80x30 = 2400 格噪声
noise = make_noise(rng, density)      # 每帧遍历 2400 格

# ✅ 每 3 帧才重新生成（爆发时每帧，保证抖动感）
if frame % 3 == 0 or intensity > 0.5:
    noise = make_noise(rng, ...)
else:
    noise = _noise_cache
```

**实测**：含故障效果后 **0.42 ms/帧（2373 fps）**，远超 18fps 需求。

# 补充：`zhdesk` 进不去 —— seatd 竞态

**症状**：`zhdesk` 执行后桌面起不来，日志显示 sway 秒退。

## 一、★ 根因：seat 被占用（不是 kmscon 的问题）

`zhdesk` 日志：
```
12:53:10 启动 sway (tty2, renderer=gles2)
[ERROR] [libseat] Could not poll connection: Broken pipe
[ERROR] [libseat] Backend 'seatd' failed to open seat: Broken pipe
[ERROR] [backend/session/session.c:92] Unable to create seat: Broken pipe
[ERROR] [sway/server.c:270] Unable to create backend
12:53:10 sway 提前退出，返回码 1
```

**真正的原因在 seatd 日志里**：
```
12:53:10 [ERROR] [seatd/seat.c:201] Could not add client: seat is VT-bound and has an active client
12:53:10 [ERROR] [seatd/seat.c:201] Could not add client to target seat: Device or resource busy
12:53:46 [INFO]  [seatd/client.c:480] Client disconnected        ← 旧 sway 终于退出
12:53:49 [INFO]  [seatd/seat.c:248] Added client 1 to seat0      ← 重试才成功
```

> **`seatd` 的 seat0 同一时刻只允许一个 client。**
> `pt35-desktop` 起的 sway 已经占着 seat，我又跑 `zhdesk` 起第二个 sway
> → 新 sway 申请 seat 失败 → 报 "Broken pipe"（libseat 把失败包装成这个）→ 秒退。

**误导点**：错误信息是 `Broken pipe` / `Unable to create seat`，
看起来像 seatd 服务挂了，实际是**座位被别的进程占着**。

## 二、修复：`zhdesk` 加三重前置检查

```bash
# 1) 已有 sway 在跑就不重复启动（这是根因）
if pgrep -x sway >/dev/null 2>&1; then
    if systemctl is-active --quiet pt35-desktop.service; then
        echo "桌面已在运行（pt35-desktop 已持有 seat）"
        echo "  直接按 Ctrl+Alt+F2 切过去；重启桌面请用 systemctl restart pt35-desktop"
        exit 0
    fi
    # 等旧 sway 退出（最多 10 秒），超时则强杀
fi

# 2) 等 seatd socket 真正就绪（不只看 is-active）
for _ in $(seq 1 20); do
    [ -S /run/seatd.sock ] && systemctl is-active --quiet seatd && break
    sleep 0.3
done

# 3) 等旧 wayland socket 消失
for _ in $(seq 1 20); do
    ls /run/user/0/wayland-* >/dev/null 2>&1 || break
    sleep 0.3
done
```

**并在 sway 提前退出时给出针对性诊断**：
```bash
if grep -q "Unable to create seat" "$LOG"; then
    log "  原因: seatd/seat 不可用 —— 可能有其它 sway 持有 seat"
    log "  排查: systemctl status seatd; pgrep -a sway"
fi
```

## 三、验证结果

```
测试 1: 桌面已跑时执行 zhdesk  → 友好提示，不破坏现有环境 ✅
测试 2: 停桌面后执行 zhdesk    → 正常启动（sway=2 foot=1 fcitx5=1）✅
测试 3: 连跑 3 次              → 3/3 全部成功 ✅
seatd 日志: 无 "active client" 冲突
```

## 四、★ 教训总结

| 坑 | 表现 | 实质 |
|---|---|---|
| **seat 竞态** | `Broken pipe` / `Unable to create seat` | **seat0 同一时刻只能有一个 client** |
| **误判方向** | 以为是 seatd 服务坏了 | 实际是有另一个 sway 占着座位 |
| **排查关键** | 一定要看 **seatd 自己的日志** | `journalctl -u seatd` 才会说出真相 |

> **规则**：`zhdesk`（手动启动）和 `pt35-desktop`（开机自启）**会争同一个 seat**。
> 平时应该用 `pt35-desktop` 统一管理，`zhdesk` 只作为手动兜底，
> 且必须先检查是否已有实例在跑。

# 补充：自定义命令的集中帮助系统

**需求**：命令越攒越多（11 个），记不住名字和用法，需要一个统一入口。

## 一、设计：元数据写在脚本自身

每个脚本头部加一行：
```bash
# help: <分类> | <一句话说明>
```
例如：
```bash
# help: 网络 | WiFi 管理（扫描/连接/状态）
# help: 桌面 | 进入中文桌面（sway + foot + fcitx5）
```

**好处**：说明永远和代码在一起，不会过期；不需要单独维护命令清单。

## 二、三个入口

```bash
pt35                    # 列出全部命令（按分类）
pt35-help               # 同上（正式名）
pt35-help <命令>        # 看某个命令的详细用法
pt35-help <关键词>      # 搜索（匹配 名字 / 说明 / 分类）
pt35 <命令> [参数]      # 直接执行（等价于直接敲命令名）
man pt35-help           # man 手册
pt35 <TAB>              # bash 补全
```

`pt35` 做成**独立可执行脚本**（不是 `.bashrc` 函数）——
因为登录 shell 不读 `.bashrc`，脚本形式在任何 shell 里都能用。

## 三、★ 危险 bug：`pt35-help pt35-poweroff` 真的关机了

**起因**：早期实现为了获取更多信息，会真的执行 `<命令> --help`。
而 `pt35-poweroff` 当时不检查参数 → **直接把机器关掉了**。

```
$ pt35-help pt35-poweroff
Connection to 192.168.1.100 closed by remote host.   ← 设备关机
```

**两层修复**：

1. **`pt35-help` 绝不执行任何脚本** —— 改为**纯源码解析**：
   从脚本里正则提取 `--help` 分支的 heredoc 文本
   ```python
   m = re.search(r"--help.*?<<\s*['\"]?(\w+)['\"]?\s*\n(.*?)\n\s*\1\s*$",
                 src, re.S | re.M)
   ```
   Python 脚本则取模块 docstring。

2. **危险命令补 `--help` / `--dry-run`**：
   ```bash
   pt35-poweroff --help      # 显示帮助，不关机
   pt35-poweroff --dry-run   # 只做检查并显示会做什么，不真关机
   ```

**验证**：8 个命令逐个测试 → **帮助全部可提取、副作用全部无**。

> **教训**：任何"为了获取信息而执行未知脚本"的设计都是危险的。
> 帮助系统必须**只读**。

## 四、踩到的其它坑

| 坑 | 表现 | 修正 |
|---|---|---|
| **`--dry-run` 文档说谎** | 帮助里写了但没实现，测试时仍走向 poweroff | 补上真实实现并验证 |
| **插错位置** | 用 `grep "执行关机"` 定位，匹配到**注释里的文档**（第 5 行），把代码插进了头部 | 改用代码特征（`if [ "$SKIP_CONFIRM"`）或行号定位 |
| **f-string 嵌套引号** | Python 3.12 不允许 f-string 内用同种引号，`f'{RED}文字{R}'` 报 unterminated | 改成字符串拼接 |
| **搜索不含分类** | `pt35 网络` 搜不到 wifi（说明里没有"网络"二字） | 搜索范围加上 `v['cat']` |

# 补充：locale 问题的排查（man 乱码）

## 症状

`man pt35-help` 显示 `????` 而不是中文。

## ★ 排查陷阱：我差点误判

我的检测逻辑写错了 —— 用**英文关键词**去 grep 中文输出：

```bash
# ❌ 错误检测：中文手册里根本没有 "PocketTerm35" 这个词
man pt35-help | grep -q "PocketTerm35" && echo "正常" || echo "乱码"
```

实际输出第 3 行是 **`名称`**（中文的 "NAME"），所以 grep 不到 → 误判为乱码。

**修正后的检测**（用真正会出现的词）：
```bash
man pt35-help 2>/dev/null | grep -q "名称" && echo "✅ 中文正常"
```

## 真正的问题：locale 没进 SSH 会话

```
/etc/locale.conf:      LANG=en_US.UTF-8   ← 有设置
localectl status:      LANG=en_US.UTF-8   ← systemd 也认
但 ssh 会话里:          LANG=空  LC_CTYPE="POSIX"   ← ❌
```

**原因**：`/etc/locale.conf` 只被 **systemd 用户会话**读取，
SSH 的**非登录 shell** 不读它，拿到的是 POSIX（= C locale = ASCII）→ 中文变 `?`。

## 修复：三层兜底

```bash
# ① /etc/environment        —— 对 PAM 会话生效
LANG=en_US.UTF-8
LC_CTYPE=en_US.UTF-8

# ② /etc/profile.d/00-locale.sh —— 对登录 shell 生效
export LANG="${LANG:-en_US.UTF-8}"
export LC_CTYPE="${LC_CTYPE:-en_US.UTF-8}"

# ③ /root/.bashrc            —— 交互式 shell（本来就有）
```

## 验证结果

| LANG | man 中文 |
|---|---|
| `C` | ❌ `??` |
| `en_US.UTF-8` | ✅ `名称` |
| `zh_CN.UTF-8` | ✅ `名称` |
| `C.UTF-8` | ✅ `名称` |

修复后登录 shell / 非登录 shell 都拿到 `LANG=en_US.UTF-8`。

> **教训**：排查编码问题时，**检测命令本身也可能有 bug**。
> 先用 `LANG=X man ... | sed -n '3p'` 看原始输出，再判断。

## ★★★ 三个致命踩坑（花了很久才定位）

### 坑 1：终端尺寸不能靠字号推算

```bash
# ❌ 我按 DejaVu 11pt 推算 → 以为 640x480 是 95 列 × 38 行
# ✅ 实测才是对的：
$ tput cols; tput lines
80
24
```
按 95×38 设计的 94 列 × 29 行页面 → **折行 + 滚屏，顶部全被推出屏幕**。

### 坑 2：★★ 块字符（█ ▓ ░ ▒ ▄ ▀）是【双宽】的！

真机像素实测：

| 内容 | 字符数 | 实测像素宽 | 折算列数 |
|---|---|---|---|
| `▓` × 10 | 10 | 108 px | **13.4** |
| `░` × 10 | 10 | 107 px | **13.4** |
| `█` × 10 | 10 | 105 px | **13.1** |
| `▄` × 10 | 10 | 197 px | **24.6** |
| `X` × 20 | 20 | 160 px | **20.0** ✅ |

**原因**：DejaVu Sans Mono **缺**这些字形 → foot 回退到
**Noto Sans Mono CJK**（CJK 全角 = 2 列）。

> **结论**：终端 UI 里这些"好看"的块字符会让**所有宽度计算失准**。
> 想稳定就**只用纯 ASCII**。

### 坑 3：foot 的 CJK 宽度与 wcwidth 不一致

即使按 `unicodedata.east_asian_width` 算好（中文记 2 列），
foot 仍会在某些中文行折行。**所以正文也只用 ASCII**，
中文留给命令自己输出（`wifi`/`temp` 的中文界面不受影响）。

## 实现要点

```bash
# 显示宽度（不是字符数！）—— 纯 bash，无 fork
_dw() {  # 返回 1 或 2
    printf -v cp '%d' "'$1"
    if   (( cp >= 0x1100 && cp <= 0x115F )); then echo 2
    elif (( cp >= 0x2E80 && cp <= 0x303E )); then echo 2
    elif (( cp >= 0x4E00 && cp <= 0x9FFF )); then echo 2   # CJK 统一表意
    elif (( cp >= 0xFF00 && cp <= 0xFF60 )); then echo 2   # 全角
    else echo 1
    fi
}
vlen() { local t i n=0; t=$(_strip_ansi "$1")
         for (( i=0; i<${#t}; i++ )); do n=$(( n + $(_dw "${t:i:1}") )); done
         printf '%d' "$n"; }

# ANSI 剥离也要纯 bash（不用 sed/awk，Pi 上 fork 一次 5-15ms）
_strip_ansi() { local s=$1 out='' rest
    while [[ $s == *$'\033['* ]]; do
        out+="${s%%$'\033['*}"; rest="${s#*$'\033['}"; s="${rest#*m}"
    done; printf '%s%s' "$out" "$s"; }
```

## 顺带修掉的桌面顽疾：wayland socket 被删

排查 MOTD 截图时发现 `/run/user/0/wayland-1` 反复消失：

```
16:58:42 Starting User Runtime Directory /run/user/0...
16:59:40 Stopping User Runtime Directory /run/user/0...   ← SSH 断开
16:59:44 Starting User Runtime Directory /run/user/0...   ← 目录被重建（空的！）
```

**根因**：root 未开 lingering（`LINGER: no`），systemd 在**每次 SSH 会话断开**时
销毁并重建 `/run/user/0` → **sway 的 wayland socket 一起被删** →
桌面进程还活着但所有客户端连不上（`grim`/`foot` 报 "no compositor running"）。

**修复**：把桌面运行时目录搬到 `/run/pt35`（由 `RuntimeDirectory=pt35` 管理，与登录会话无关）

```ini
[Service]
RuntimeDirectory=pt35
RuntimeDirectoryMode=0700
Environment=XDG_RUNTIME_DIR=/run/pt35
```

并把 `zhdesk` 里的
`export XDG_RUNTIME_DIR="/run/user/$(id -u)"`
改成
`export XDG_RUNTIME_DIR="${XDG_RUNTIME_DIR:-/run/pt35}"`（尊重外部传入值）。

**验证**：断开 SSH → 重连 → socket 仍在（inode 未变）→ `grim` 截图成功。
